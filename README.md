# Distributed Log Aggregator & Indexer

### LogFlow – A Distributed Log Processing and Monitoring System

## 1. About the Project

The **Distributed Log Aggregator & Indexer** is a Python-based system designed to collect, process, store, index, and monitor log messages generated by multiple simulated servers.

The system uses **Amazon Simple Queue Service (SQS)** as a centralized cloud message queue to manage incoming logs. A dynamic worker management mechanism automatically adjusts the number of Python worker threads according to the queue workload.

Processed logs are stored in an SQLite database, while an inverted indexing mechanism enables efficient keyword-based searching. A Flask-based web dashboard provides centralized monitoring, visualization, filtering, and analysis of the generated logs.

## 2. System Architecture

The project follows a distributed log-processing architecture:

**Log Generator → Queue Manager → Amazon SQS → Dynamic Worker Manager → Worker Threads → SQLite Database & Inverted Index → Flask Backend → LogFlow Dashboard**

## 3. Key Features

- **Automatic Log Generation:** Generates log messages from three simulated servers: SERVER-1, SERVER-2, and SERVER-3.
- **Dynamic Workload Simulation:** Simulates normal, increasing, spike, heavy, and decreasing workload phases.
- **Cloud Message Queue:** Uses Amazon SQS to temporarily hold incoming log messages.
- **Batch Message Publishing:** Publishes log messages to SQS in batches to reduce individual publishing requests.
- **Dynamic Worker Scaling:** Automatically increases or decreases Python worker threads according to queue workload.
- **Concurrent Processing:** Multiple worker threads process log messages concurrently.
- **Database Storage:** Stores processed log records in SQLite.
- **Inverted Indexing:** Supports efficient keyword-based log searching.
- **Interactive Dashboard:** Displays log statistics, workload information, queue status, worker activity, and log records.
- **Log Filtering:** Supports searching and filtering logs based on relevant criteria.
- **CSV Export:** Allows users to export log records for further analysis.

## 6. System Workflow

1. The automatic log generator creates log messages for the simulated servers.
2. The Queue Manager collects and publishes messages in batches to Amazon SQS.
3. Amazon SQS temporarily stores incoming messages until they are processed.
4. The Dynamic Worker Manager monitors the approximate queue workload.
5. Python worker threads are dynamically increased or decreased according to the workload.
6. Workers retrieve messages from SQS and process them.
7. Successfully processed logs are stored in the SQLite database.
8. The inverted index is updated to support keyword-based searching.
9. Successfully processed messages are acknowledged by deleting them from the SQS queue.
10. The Flask backend provides system information and log records to the dashboard.
11. The LogFlow dashboard displays the processing activity and system statistics.

## 7. Installation and Setup

### Prerequisites

- Python 3.x
- Git
- An AWS account with permission to access Amazon SQS
- An Amazon SQS queue

### Step 1: Clone the Repository

```bash
git clone https://github.com/JeegnasaMak/Distributed-Log-Aggregator-68-69.git
```

### Step 2: Navigate to the Project

```bash
cd Distributed-Log-Aggregator-68-69
```

### Step 3: Create a Virtual Environment

```bash
python -m venv .venv
```

Activate it on Windows:

```powershell
.\.venv\Scripts\Activate.ps1
```

### Step 4: Install Dependencies

```bash
pip install -r requirements.txt
```

### Step 5: Configure AWS Credentials

Create a `.env` file in the project root using `.env.example` as a reference.

Configure the following variables:

```env
AWS_ACCESS_KEY_ID=your_access_key
AWS_SECRET_ACCESS_KEY=your_secret_key
AWS_SESSION_TOKEN=your_session_token
AWS_REGION=us-east-1
SQS_QUEUE_URL=your_sqs_queue_url
```

Use valid AWS credentials and ensure that the account has the required SQS permissions.

### Step 6: Run the Application

```bash
python src/app.py
```

### Step 7: Open the Dashboard

Open your browser and visit:

```text
http://127.0.0.1:5000
```

## 8. Important Notes

- AWS credentials and the actual `.env` file are not included in this repository.
- Users must configure their own AWS credentials and SQS queue.
- Amazon SQS is used for temporary message queuing, while SQLite stores processed logs locally.
- Worker threads execute locally on the system running the application.
- The maximum number of workers is controlled by the worker manager configuration.
- AWS usage may incur charges depending on the account and service usage.
